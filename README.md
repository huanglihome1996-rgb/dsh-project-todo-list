# DSH 项目待办列表

[![GitHub release](https://img.shields.io/github/v/release/huanglihome1996-rgb/dsh-project-todo-list)](https://github.com/huanglihome1996-rgb/dsh-project-todo-list/releases)

**在 DSH 项目的新会话中，优先看到真正需要你处理的下一步任务。** AI 结合主分支项目文档、GitHub Issue 与本人分支的进度线索，筛选、排序并估算工作量；点击任务只填入执行建议，不自动发送。

## 功能

- 只在**已选项目工作区、尚未发送第一条消息的新会话**输入框下方显示紧凑列表；已有会话不会出现。
- 优先分析 Git 主分支已提交的 README、计划和需求文档；本人有独立提交的其他分支仅作为归属和进度的辅助线索。读取通过 Git 对象完成，**不切换分支、不改项目文件**。可选读取 GitHub 未关闭 Issue（需已登录 `gh`）。
- AI 根据任务上下文判断是否属于本人并且有具体下一步。仅被提及、抄送或 `@` 不足以构成任务；每项结果需要可在来源中核对的归属和动作证据。估算「紧急／高／普通／低」优先级和四档粗略工作量，优先级高的排前面。
- UI 默认展示一项推荐任务，可展开其余任务；标记「未开始／进行中」，以柱条展示粗略工作量。点击后在本地关联当前会话，填入包含分支检查、实施、测试、文档同步和阻塞时先问用户的详细提示词。
- 每个正常完成的会话轮次结束后，AI 结合会话结果判断关联待办是否已完成；证据不足或遇到阻塞则保持「进行中」，不会草率标记完成。
- 12 小时后**下次打开列表时**自动更新，仍可手动刷新。缓存即时显示、后台分批核验，优先呈现已核验的主分支文档任务。

## 安装

要求 DSH `0.2.2-rc.1`、Node.js ≥22，使用带 Web GUI 的 DSH profile。建议在 **插件市场 → 添加索引** 中填入本仓库的市场索引 URL（发布版本后见下方），搜索「项目待办列表」并安装；也可以在插件管理器中使用 GitHub Release 页面标明的固定提交版本进行安装。Git 安装会按索引锁定提交，不依赖浮动分支。

市场索引：`https://raw.githubusercontent.com/huanglihome1996-rgb/dsh-project-todo-list/main/market/index.json`

若从源码本地安装，可在 DSH 中调用插件管理器 `install_bundle`，目标填写本仓库的绝对目录。启用后打开已有项目工作区的**新会话**。

## 使用与配置

- **刷新**：列表右侧刷新按钮；自动刷新不是常驻后台定时任务。
- **归属身份**：默认读取项目 Git 用户名/邮箱、GitHub 登录名；如果与项目文档称呼不一致，可在插件配置设置 `name`、`aliases`。
- **AI 模型**：默认使用当前 DSH 默认模型；可在插件配置显式设置 `provider`、`model`，可选 `timeoutMs`、`maxTokens`。
- **GitHub Issue**：需安装 GitHub CLI、先 `gh auth login`，且项目 `origin` 指向 GitHub；未满足时退化到本地项目文档。
- **缓存路径**：`$DSH_HOME/project-todo/`，默认 `~/.dsh/project-todo/`。待办状态和关联会话只保存于 DSH 本地，不会推送或写入项目代码。

## 隐私与限制

候选任务及附近的项目文档文本会发给配置的 AI 模型做归属与优先级分析；项目包含保密内容时，请选用符合项目数据政策的模型。本插件不自动提交消息、不自动执行任务，也不会自动向 GitHub 修改 Issue。首次没有缓存时仍需等待项目资料读取和首批模型核验。AI 判定、工作量和完成状态是辅助判断，不保证准确；不确定的任务默认不显示，手动刷新可重新分析。DSH 没有独立的「整个会话结束」事件，因此完成检查在每个正常结束的会话**轮次**执行。
