# 项目待办（DSH 本地插件）

仅在已选项目工作区、尚未发送第一条消息的新会话输入框下展示待办。优先读取 Git 主分支已提交的 README、计划、需求等文档，并结合 GitHub 未关闭 Issue；本人提交的其他分支仅用来辅助判断进度和任务归属，不会切换或修改当前分支。AI 综合职责与上下文判定个人下一步任务，不再要求每项都有固定格式的“负责人”字段；仅提及、抄送或 `@` 用户及无具体下一步的内容仍会过滤。模型必须给出可在来源中验证的归属与动作证据。AI 还评估紧急/高/普通/低优先级及轻量/中等/较大/大型的粗粒度工作量，列表按优先级排序。待办标题采用简洁动宾短语，明确标识「未开始」「进行中」。点击任务先在 DSH 本地关联当前会话，再填入详细执行提示词（分支检查、实施与测试、同步项目文档、阻塞时先征询用户）；不会自动发送消息。

插件会将最多 60 个候选项分批提交至当前配置的模型进行判断；项目文档原文会发往该模型服务，请按项目保密要求使用。可在配置中指定 `provider` 与 `model`。每个正常结束的会话轮次后，插件会根据该会话结果和证据判定是否完成当前关联待办；证据不足、阻塞或模型不可用时保持「进行中」。扫描结果在上次扫描满 12 小时后的下一次列表读取时自动刷新，也可以随时手动点击刷新。界面先立即展示本地缓存的已核验重要待办；首次无缓存时先返回加载状态，主分支文档的首批 AI 核验结果可先显示，Issue 和后续批次完成后渐进更新。更新期间仅短时轮询进度，不会永久轮询。刷新与完成状态仅保存在 `$DSH_HOME/project-todo/`（默认 `~/.dsh/project-todo/`），不会写入项目仓库。GitHub Issue 仅在本机已安装且登录 `gh`，且项目 remote 指向 GitHub 时读取；无法访问时仅分析本地文档。身份由项目 Git 用户名/邮箱、GitHub 登录名及可选 `name`、`aliases` 配置交叉确认。
